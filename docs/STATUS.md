**D-12 root cause (measured, not guessed).** The Volume popover closes itself 3 s after it opens unless it holds pointer or focus (`VolumeModal.tsx` `AUTO_CLOSE_MS`, NGU behaviour). `e2e/shell.spec.ts:178-186` clicks Mute, then runs `expectOnScreen` (visibility, bounding box, `evaluate`) and a full-page `shot()`. On mobile Chrome under software WebGL that sequence takes more than 3 s, so the popover unmounts between the visibility check and the `evaluate`. The detached node reports a `0,0,0x0` rect and `elementFromPoint` returns the canvas, which the test reads as "something covers the element's centre". Every retry in the `toPass` loop hits the same race, so it burns the 60 s and then the 90 s test timeout. A scratch copy of the test (session scratchpad, not in the repo) logged `node=DIV.popover|Volume|dialog rect=0,0,0x0 top=CANVAS`. The component is correct; the test is racy. Scratch fix, measured: focus the slider before checking (`await volume.getByRole("slider", { name: "Volume" }).focus({ timeout: 5000 })` right after the click, which the popover treats as "keep open" via `onFocus={pause}`), 20 of 20 pass at 3 workers against 9 of 20 and 4 of 12 failing for the unmodified copy. The test body was W3's; it passed 126 of 126 at W3 close, and the machine is now loaded with more Pixi work per page, so the margin is gone. No product code change is needed.

## 2. How the board works

- **Gate commands** (every task reports all that apply): `pnpm lint`, `pnpm exec tsc --noEmit`, `pnpm exec vitest run --coverage`, `pnpm build`, `pnpm typecheck:server`, `pnpm test:server`, `pnpm e2e:test --reporter=line`. The last three exist since W1-B1. `playwright.config.ts` keeps the `html` reporter for humans; agents always pass `--reporter=line`.
- **Disjoint files.** No two tasks in a wave touch the same file. Shared files (`package.json`, `vite.config.js`, `src/styles/*`, `src/App.tsx`, `src/components/DebugMenu/**`, `e2e/helpers.ts`) have exactly one editing task per wave, named in that task's Files line. A task that needs one of those files and is not named reports the gap instead of editing.
- **Contract first.** A task that needs a wire change stops and tells the lead; the PM edits `docs/API-CONTRACT.md`, then the backend implements it.
- **Debug rule (TEAM.md override 4).** Each task lists the debug controls its feature needs. They ship in the same task.
